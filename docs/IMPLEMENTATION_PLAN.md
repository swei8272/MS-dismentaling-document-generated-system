# 实施计划

每个阶段必须独立完成、测试和验收。上一阶段未通过时，不进入下一阶段。

## 第一阶段：批次与任务基础

实现数据库迁移、batches、batch_images、图片任务状态、批次页面、只保存不 OCR 的上传流程和任务领取接口。

退出条件：`docs/ACCEPTANCE_CRITERIA.md` 中第一阶段条件全部通过。

## 第二阶段：分块上传与进度

- 浏览器选择大量图片；
- 自动拆成每组 20–30 张上传；
- 显示上传进度和失败重传；
- 支持向已有批次补充图片；
- 页面刷新后可以恢复批次状态。

退出条件：500 张图片上传期间页面可访问，单组失败可以继续。

## 第三阶段：后台 OCR Worker

- 独立 Worker 循环领取任务；
- 加载 OCR 模型一次；
- 单张失败隔离；
- 失败重试和超时恢复；
- Worker 停止不影响 Web。

退出条件：重启 Worker 后可以继续未完成任务。

## 第四阶段：RTX 3090 GPU OCR

- 安装并锁定兼容的 CUDA OCR 依赖；
- 检查 GPU provider；
- 显示当前 OCR 后端；
- 无 GPU 时提供明确诊断；
- 记录单张耗时、显存和吞吐量。

退出条件：实际 OCR 进程使用 RTX 3090，并通过样本准确性测试。

## 第五阶段：图片分类和字段提取

- 区分车辆照片、行驶证、微信截图等类型；
- 提取 14 个标准字段；
- 保存 OCR 原文、字段来源和置信度；
- 缺失字段保持为空。

退出条件：代表性样本的车牌、VIN、业务归属和进场时间结果可人工核对。

## 第六阶段：车辆关联与人工确认

- 车牌号和 VIN 强匹配；
- 冲突检测；
- 待确认页面；
- 人工分配图片；
- 后续图片补全车辆记录。

退出条件：混合上传不会静默串车，人工确认可以正确更新车辆。

## 第七阶段：批次表和总表

- 新增 batch_vehicles 关系；
- 每批次一车一行；
- 生成 14 列批次表；
- 生成最新车辆总表；
- 缺失值导出为“暂无”；
- 人工修改后可重新生成。

退出条件：跨批次已有车辆不在总表重复出现。

## 第八阶段：部署与恢复

- Web 和 Worker 开机自动启动；
- 局域网访问；
- 日志轮转；
- 数据库自动备份；
- 低磁盘空间提示；
- 恢复演练和使用说明。

退出条件：普通工作人员可以按说明启动、上传、确认和导出。

## 第九阶段：压力和业务验收

- 100、500、1000 张图片测试；
- 页面响应、内存、GPU、磁盘和数据库监测；
- Web/Worker 重启恢复；
- 重复、损坏、超大和低清图片测试；
- 真实车辆批次与人工表格对照。

退出条件：无数据丢失、无重复车辆、无静默错误，性能满足实际每日工作量。
