## 目标和范围

将参考软件中的证件分类、识别回填、车辆资料夹和候选人工确认交互，独立实现到铭深文件生成系统。保留“先混合批量上传，再自动整理”的主要入口，同时补充单车资料管理。

| 纳入本轮方向 | 实现要求 |
| --- | --- |
| 本机 OCR | 独立 Worker；记录实际后端；网页不加载模型 |
| 资料分类 | 车辆照片、行驶证、登记证书、身份证正/反面、企业证件、微信截图、回收/注销证明、其他/不确定 |
| 字段提取 | 固定 14 个标准字段，候选值能追溯原图与 OCR 原文 |
| 车辆管理 | 车牌/VIN 搜索、车辆详情、分类资料、字段来源、处理进度 |
| 关联复核 | 强标识匹配、候选车辆选择、无标识待确认、字段冲突处理 |
| 单车补传 | 仍属于明确批次，沿用上传回执、SHA-256 去重与任务队列 |
| 证件状态 | 人工维护并保留历史；不从上传成功推断官方手续完成 |
| 表格衔接 | 每批次和总表固定 14 列、同车一行、修正后可重新生成 |

称重核算、结算付款、银行卡管理、拖车调度、生产拆解、仓储、销售、全厂 ERP 留待后续。现有图片中即使包含相关内容，也只按原业务规则保存证据/OCR 原文，不新增标准表列。

继续 Windows 10/11、Flask/Waitress、SQLite、单个独立 OCR Worker、RTX 3090 本机识别；资料默认本地保存，通过厂内局域网网页访问。首版不新增 Android 工程、云服务或 Redis/Celery。

## 页面和操作

### 批次管理

保留现有页面、分组上传、失败重传、回执和分页。分别显示“文件已保存”“OCR 状态”“关联/复核状态”；不能把传输结束显示为车辆整理完成。

阶段六提供从批次查看所涉及车辆、待确认图片和冲突的入口。需要的批次车辆关系可先按已有证据关联查询，第七阶段再按实施计划新增/完善 batch_vehicles；阶段六不要求提前建立第七阶段专属表。

### 车辆列表与详情

车辆列表：车牌/VIN 搜索、批次及资料处理状态筛选、分页。强匹配使用完整规范化标识；列表模糊搜索结果不参与自动匹配。

详情包含：
- 14 个标准字段及缺失提示；
- 分类照片和原图预览，分页/懒加载；
- 字段候选、确认结果和证据来源；
- 关联批次、后续补传、待复核原因；
- 人工修正与证件状态历史。

能看见照片不等于字段已核实。原始照片不可因裁剪、旋转、识别或人工修正被覆盖。

### 待确认与冲突复核

区分 OCR 失败、分类不确定、车辆不确定、字段值冲突。OCR 失败可重试；其余情况应允许人工处理已有结果，不默认重复 OCR。

复核页并列显示原图、OCR 原文、候选字段和候选车辆。没有候选时允许人工搜索已有车辆，或明确新建待完善车辆。人工新建不能以空车牌/VIN触发自动合并。

确认关联是单独的业务操作，有当前版本校验；已经关联其他车辆的证据不能因再次上传而静默改归属。修正归属要显示影响并记录原/新车辆及理由。

### 单车补传

进入某车辆详情后选择文件时，同时明确已有批次或新建补传批次。上传记录中的目标车辆只是人工选择上下文：
- 上传请求仍只保存/入队，不执行 OCR 或车辆匹配。
- 用户明确确认后可关联；如果后续 OCR 发现车牌/VIN矛盾，必须标记复核并保留证据，不能静默覆盖或转移。
- 已被其他车辆占用的重复证据进入冲突流程。
- 已完成图片跨批次复用不重新识别，仍正确体现新增批次关系。

### 证件状态

`document_status` 表示人工确认的业务状态；证据类型/照片是否存在单独保存。存在注销证明照片、识别成功或模型判断均不能自动写成“已完成注销”。
`deregistration_required` 与是否上传了手续照片互相独立。初期不强制增加未经确认的枚举流程，提供可校验的人工维护和变更记录；是否细分状态另按实际业务确定。

## 字段与识别规则

以 [BUSINESS_RULES.md](BUSINESS_RULES.md) 为唯一标准列定义，共 14 个，顺序不变：

self_number、plate、vehicle_type、brand_model、owner_name、vin、
engine_number、registration_date、curb_weight_kg、business_owner、
transport_method、arrival_time、deregistration_required、document_status。

- 缺失存 NULL；“暂无”只用于显示/导出，不能写回真实字段；0 与缺失分开处理。
- `business_owner` 保留“某某送来的车辆”等完整表达，不以运输司机/车主自动替代。
- `curb_weight_kg` 仅提取整备质量；总质量、过磅净重、参考重量不能替代。
- 品牌型号保存可核对的整体文本，不能简单按中文/英文拆分丢失信息。
- VIN/车牌保留原文与规范值；疑似 OCR 字符替换只能作为候选，不能静默修复后强匹配。
- 日期、时间只保留证据支持的精度；未出现时分秒不自行补成实测进场时间，时区沿用/明确本地业务口径。
- 各字段保存来源 evidence_id、原始文本、规范化值、提取方式及可用置信信息。后端不提供置信度时记为空，不能伪造高分。
- 图片可能含多个证件类型；分类可为不确定/多类型候选，不能强迫每图唯一正确类别。
- 身份证可作为资料类型，相关原文按原规则保留；不新增身份证号/银行卡号标准列，也不建立全量身份证搜索作为默认能力。
- 初期不实现参考软件的云端“身份证自动找车”。复现候选列表与人工确认交互；候选来源限定车牌/VIN，姓名只作展示辅助。

## 车辆关联规则

| 情况 | 必须处理 |
| --- | --- |
| 单一可靠车牌完整匹配一辆车，VIN无矛盾 | 关联该车辆，空字段可补全 |
| 单一可靠 VIN 完整匹配一辆车，车牌无矛盾 | 关联该车辆，空字段可补全 |
| 车牌指向 A、VIN 指向 B | 待复核；A/B均不覆盖 |
| 车牌匹配A但新VIN与A现有VIN不同 | 待复核，不把新VIN补到A |
| VIN匹配A但新车牌与A现有车牌不同 | 待复核，不自动当作车牌变更 |
| 任一强标识匹配多个旧记录 | 待复核，报告重复记录；不任取首条 |
| 图片含多个车牌或多个车辆VIN | 待确认，不能按位置/顺序自动串车 |
| 无可靠强标识 | 保留证据待人工归档 |
| 只有姓名、品牌、车型或上传顺序相同 | 禁止自动关联 |
| 新强标识未匹配且内部一致 | 原子查重后新建，并发不能重复车辆 |
| 同字段不同非空值 | 保留已确认值与新候选，人工选择后写历史 |

图像分类/字段提取阈值需按脱敏代表性样本校准，不从 APK 猜测或为提高覆盖率放宽安全关联条件。

## 现有代码复用与数据设计

已核对 main 的 database.py：
- vehicles 已包含 14 字段；plate/vin 当前是非唯一索引。
- evidence 已有 ocr_text、extracted_json、processing_status、attempt_count。
- batches、batch_images、schema_migrations 和全局图片去重已有实现。
- `claim_next_queued_evidence` 和三个终态函数已校验领取版本。
- 现有终态函数只更新任务状态，没有实现完整 OCR 结果/字段/车辆原子落库。

实施时按合并后的实际代码再次核对，不复制一套并行数据库层。

1. 迁移版本从当时最新 schema_migrations 递增，不能预占第二阶段迁移号或改写历史迁移。
2. 阶段三优先复用 ocr_text/extracted_json；识别原文和任务终态同事务提交，事务内校验 id、processing、领取时 attempt_count。
3. 过期 Worker 不得写 OCR 原文、字段候选或车辆记录；失败分支也不得破坏新领取结果。
4. 阶段五按需要新增分类/字段候选结构；阶段六按需要新增证据车辆关联、冲突和人工修正历史。实际表名/列在阶段 Issue 和迁移中明确。
5. 自动匹配的“检查已有车辆—创建/关联—补空字段—冲突留存—任务状态/批次统计”须有原子性。OCR计算在数据库写事务外完成。
6. 新增唯一约束前检查旧重复数据；发现异常先报告，不删除车辆、不清空数据库解决。
7. 人工复核使用版本比较并交换；过期页面提交应提示刷新，不丢失前一次修正。操作、前后值、时间、原因、请求标识同事务记录。
8. 当前没有登录。人工事件记录实际可得的操作来源，可让操作人自报姓名，但必须标明非认证身份；不宣称具备账户级审计，不顺带建设全厂角色系统。
9. 第七阶段批次表和总表以最新已确认值生成，写临时文件成功后原子替换。导出读一致快照，并记录生成时间/数据版本；人工修正后明确提示需重新生成旧导出。
10. 所有测试使用隔离数据库、合成或脱敏图片，不访问真实生产 data/uploads/exports。

第三阶段尚无自动归档时，OCR 已返回但尚未分类/归档的图片应明确显示该状态；如沿用 pending，原因写“识别完成，等待后续归档”，不能把它写成 OCR失败。后续阶段处理应复用已存 OCR，不能靠重新上传所有图片迁移进度。

第三阶段可用 fake OCR 测试生命周期/故障，但 fake 结果只证明控制流，不能作为真实识别验收。运行环境缺模型/GPU时明确列出未验证项，不下载或调用原厂服务器代替。
