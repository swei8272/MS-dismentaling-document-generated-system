# 第二阶段实施指令

本阶段由 GitHub Issue #4 明确授权。第一阶段 PR #3 已合并；第二阶段直接修改
代码、测试和文档，不再请求阶段切换确认。

## 目标

录入员一次选择数百张图片后，浏览器自动拆成受控小组串行上传，逐文件显示
服务端确认结果；临时错误有限重试，失败文件可手动重传。刷新后以服务端已
保存数据和持久化上传失败记录为准，并允许向已有批次继续补充图片。

## 必须实现

### 浏览器分组与资源限制

- 默认每组最多 25 张、文件净大小合计最多 64 MiB，同时最多一个上传请求在途。
- 单文件默认最多 16 MiB；单文件超限只拒绝该文件，其余文件继续。
- 使用 `File`、`FormData` 和 `XMLHttpRequest.upload`，不得把整批转为 Base64、
  ArrayBuffer 或同时解码预览。
- 本地选择列表分段渲染；无缩略图时不得为预览占用图片解码内存。
- 保留普通 multipart 表单兼容入口；本阶段不做单文件字节级断点续传。

### 上传结果与进度

- JSON 请求中的每个文件携带请求内唯一 `client_id`，逐文件返回 `added`、
  `reused`、`already_in_batch` 或 `failed`，不得只按文件名关联。
- 页面分别显示已选、服务端已确认、上传中、等待、失败/未确认和重试中。
- 字节传输达到 100% 后显示“服务器确认中”，收到 JSON 成功结果后才计入确认。
- 图片保存完成只表示进入或复用 OCR 队列，不得显示为 OCR 已完成。
- 提供轻量批次状态和分页图片接口；轮询默认 2 秒且禁止请求重叠。
- 用户可理解的错误不得包含本机完整路径或异常堆栈。

### 重试与刷新恢复

- 网络超时、HTTP 408/429/5xx 和服务端标记的临时错误最多自动重试 2 次，
  采用退避；一组失败不阻止后续组。
- 格式错误、空文件、大小和分组上限错误不自动重试。
- 提供仅重试失败/未确认且浏览器仍持有 `File` 对象的操作。
- 响应丢失时允许安全重传；始终由 SHA-256 和批次唯一约束决定去重，不按
  文件名或文件大小跳过。
- 刷新后恢复服务端状态，并明确提示本地 `File` 对象无法静默恢复，用户需
  重新选择未确认文件或整批文件。
- 上传失败持久化在独立表中，不创建伪造 evidence，不污染 OCR failed 统计；
  成功重试可把对应失败记录标为 resolved。

### 数据库与队列保护

- 新增版本 2 迁移，只创建 `upload_failures` 表和索引，不改写版本 1。
- PR 审查后的恢复修复使用新增版本 3 迁移，不改写已执行的版本 2：增加按
  `batch_id + client_id` 唯一的上传成功回执，并记录解决失败所使用的
  evidence。迟到或重复的失败补写不得重开已经确认的记录。
- 迁移必须支持版本 1 无损升级并可重复执行。
- 保持 evidence 全局 SHA-256 去重、batch_images 唯一关联及已完成图片不重排队。
- 保留任务领取版本保护：终态更新必须使用领取时的 `attempt_count`，并在同一
  条 `UPDATE` 中校验任务 ID、processing 状态和版本。
- 上传、状态和分页请求不得加载 OCR、提取字段、合并车辆或领取任务。

### 失败记录恢复补充约定

- 轻量状态轮询只返回未解决数量和变更标识；完整失败记录通过默认 25 条、
  最大 100 条的分页接口查询。
- 重新选择文件必须从具体失败记录发起，并携带该记录的 ID 与 client_id；
  文件名和大小可以改变，服务端在同一事务内校验批次、关联图片、写入回执并
  解决失败。不得按文件名或大小隐式关联。
- 已校验文件先停留在 `.incoming`；服务端在写事务内再次核对 client_id、失败
  记录和回执后才落到正式内容寻址路径。事务失败只清理本请求新建的文件。
- 浏览器断网待同步队列只保存 client_id、显示文件名、大小、失败类型和创建
  时间，不保存图片内容或 File 对象。页面加载、`online` 事件和用户手动操作
  各触发一次有界同步，每次最多自动重试 2 次并退避。
- 刷新后必须明确提示重新选择文件；成功上传与失败补写交错时，以服务端上传
  回执为准，失败补写返回 `already_confirmed` 且不得生成未解决记录。
- 迁移前已标记 resolved、但没有解决证据引用的历史失败记录不得猜测回填；内容
  身份无法验证时应保留数据并拒绝重复关联。

## 验收

- 原有 27 项测试和新增第二阶段测试全部通过。
- 自动化覆盖逐文件 JSON、同名不同图、同图不同名、跨批次复用、损坏图混合、
  响应丢失重传、大小/组数限制、失败记录分离、手动重试、刷新恢复和分页。
- 在真实浏览器验证自动分组、进度、服务器确认、错误提示、有限重试和刷新流程。
- Windows / Waitress 使用 500 张内容不同的合成图片验证；记录分辨率、单图及
  总大小、分组配置、耗时、前后端内存、成功/失败/去重和数据库数量。
- 上传期间每秒访问批次状态或列表，记录响应时间 p95、最大值和 HTTP 失败数；
  本机回环目标 p95 不超过 2 秒且 HTTP 失败为 0。
- 单独混入损坏图片并模拟网络中断，验证失败可见、后续组继续、可重传且最终
  数量正确。
- 运行完整 pytest、Python 编译、迁移重复执行、依赖检查、静态安全检查和
  Waitress 最小启动验证。
