# 验收标准

## 第一阶段功能验收

- 可以创建批次并生成正确的每日递增编号。
- 可以向指定批次上传图片。
- 上传后立即返回页面，不加载或调用 OCR。
- 新图片进入 queued 状态。
- 批次页面正确显示各任务状态数量。
- Web 或电脑重启后批次和任务仍然存在。
- 旧数据库自动升级且原车辆、图片和关联不变。
- 同一批次重复图片不重复关联。
- 跨批次重复图片复用 evidence，但两个批次都能查看。
- 已完成图片再次上传时不重新排队。
- Worker 接口可以原子领取任务。
- 同一任务不能被两个领取操作同时获得。
- 失败任务保存错误原因。
- 超时 processing 任务可以恢复为 queued。

## 第一阶段自动化测试

至少覆盖：

1. 全新数据库初始化；
2. 旧数据库无损迁移；
3. 迁移幂等性；
4. 批次编号递增和唯一性；
5. 同批次图片去重；
6. 跨批次图片复用；
7. 新图片排队；
8. 历史图片 completed；
9. 上传不调用 OCR；
10. 上传不调用 merge_evidence；
11. 原子领取；
12. 状态完成、待确认和失败；
13. 超时任务恢复；
14. 批次统计；
15. 重启后持久化；
16. 原有车辆、待确认和 Excel 测试回归。

测试必须使用临时数据库和临时图片目录，不能访问真实业务数据。

## 质量检查

- 全部测试通过。
- Python 编译检查通过。
- 不存在硬编码的 `D:\Codes\DGM` 业务路径。
- 不存在上传请求内 OCR 调用。
- 不存在破坏性数据库初始化。
- SQL 使用参数绑定。
- 页面能够显示中文且没有明显模板错误。
- README 与实际启动方式一致。

## 最终系统验收（后续阶段）

- 500–1000 张图片上传时 Web 保持可访问。
- RTX 3090 被 OCR Worker 实际使用。
- Worker 重启后继续未完成任务。
- 同一车辆跨批次不会在总表重复。
- 批次表和总表只包含规定的 14 列。
- 缺失值显示“暂无”，后续资料能够补全。
- 不确定图片不会被静默分配到错误车辆。
- 数据库、图片和导出文件可以按说明备份和恢复。
